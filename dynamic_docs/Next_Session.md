## This session's work, for context

- **Base Charts rewritten as standalone artefacts** (Architecture Decision 18) — one file per `chart_type_ref` under `base_charts/{shape}/`, no shared helpers module, `report_context` dropped from every chart's signature in favour of reading the `"Selected"`-labelled `population_layers` entry (this also fixed a real inconsistency in how `ranked_column`/`dot_strip` used to find the Selected unit). The formal **chart_inputs** contract term (`population_layers, width, height, tweaks`) comes from this work.
- **Custom Charts feature, built and confirmed working live** — a user can download a self-contained bundle for any chart (contract + complete current code + live data), hand it to an AI, paste the result back in, get it statically validated and live-previewed, and save it as a new chart permanently added to the workfile — indistinguishable from a built-in from that point on, everywhere a chart type is listed or resolved. New package: `core/output_generation/execution/charts/custom_charts/` (`contract.py`, `gate.py`, `resolve.py`, `bundle.py`). Storage mirrors the manifest/cache pattern in `WorkfileState` and the `.cgw`. See Architecture Decision 18 and Functional Spec §10.9 for the full account.
- **Two real bugs found via live testing, both fixed** — `bundle.py` was extracting only the target function's source, not its whole module, silently dropping every helper the function actually depends on; `gate.py` was rejecting any file with more than one function at all, when every built-in legitimately has several helpers alongside its one chart_inputs-signature entry point. Both fixed this session — worth remembering as the kind of gap that only surfaces once real code goes through the pipeline, not from reading the code alone.
- **All six governed documents reviewed; four updated.** Functional Spec (new §10.0, §10.9, light edits elsewhere) and Architecture (Section 4/5/6, new Decision 18) were updated first. On a second pass, Feature List and Glossary turned out to need changes too — and the review caught two genuine staleness bugs, not just missing new content: Feature List's `insert_chart` row and Glossary's `ReportContext` entry both still claimed charts receive `report_context`, which this session's rewrite removed. Both corrected. Worth remembering next time a chart-related change lands: check Feature List and Glossary alongside Functional Spec/Architecture as a matter of course, not as an afterthought — this session nearly closed down without them.
