- **No specific next feature named at close of this session.** Output Tables (this session's whole build) is functionally complete for its first pass -- ask rather than assume a direction; the user may want testing/refinement time before the next big feature.
- **Custom Tables have never been round-trip tested.** Built and wired end to end this session (download bundle, paste-back validate-and-preview, save as new `table_type_ref`), but no chart type or genuinely new table has actually been taken through the full loop. Worth doing before treating it as proven, the same caveat Custom Charts still carries.
- **PDF image resolution is an accepted, understood limitation, not an open bug to keep chasing.** See Architecture Decision 26 and Current_State's "Resolved/Known gaps" -- every accessible lever (rendering DPI, `autoCompressPictures`, `SaveAs` vs `ExportAsFixedFormat`, LibreOffice, third-party PDF printers, slide-image reassembly, Adobe Acrobat automation) was reviewed this session and either tested-and-ruled-out or rejected on a real constraint (licensing, losing hyperlinks/selectable text, a different rendering engine's fidelity risk). Don't re-litigate this from scratch without a genuinely new angle -- if it comes up again, start from Decision 26 and this file's account, not from zero.
- **`chart_type_ref` -> `base_chart_name` rename is agreed but deliberately not started.** Real breaking change (file version bump, every existing workfile stops opening) -- needs its own dedicated session. Wait for the user to explicitly ask to start it.
- **Chart-component cells (`{n}`) in Output Tables are parked, not built.** Recognised by the grid's own grammar, not resolved or rendered. Was deliberately descoped at the very start of the Output Tables design conversation, alongside the decision to build Custom Tables in full instead -- pick this up only if asked.
- **A manually-created Output Table has no automatic Running Order placement.** Only template-extracted (yellow-box) tables get an `insert_table` row for free; a tab-created table needs a manual Save to Running Order.

## This session's work, for context

- **Output Tables -- a full new content-construction pathway, built from a from-scratch design conversation through to a working, debugged feature.** Mirrors Charts/Base Charts throughout: grid authoring (own tab, own spreadsheet-shaped storage, Excel round-trip with a Stat Tag dropdown), a ten-strong Base Table library (`table_inputs` contract: content/column_widths/row_heights/width/height/tweaks -> image bytes), Custom Tables (download/paste-back/validate/preview/save, identical mechanism to Custom Charts but its own independent contract file, deliberately not shared across the two rendering domains), and `insert_table` as the Running Order function. See Architecture Decisions 23-24, Functional Spec Section 11.2, Feature List's new section, and Current_State for full detail -- worth reading in full before touching any of this again.
  - **Design sequence, if it helps to know the reasoning trail:** table sizing/formatting was explicitly deferred first; then the "double selection" UI was corrected into one shared "Select Table" box driving both Edit Grid and Preview; then a `- Saved Table -` placeholder was added so nothing shows on arrival; then Custom Tables were built in full on request, with chart-component cells explicitly parked rather than attempted.
  - **Two real cross-cutting bugs surfaced and were fixed, not just this feature's own:** a table/chart sizing clamp (removed, see Decision 25 -- affects the *chart* rendering path too, not just tables) and a Streamlit widget-mount timing issue in the new Preview sandbox specifically. Both are done; nothing pending from either.
  - **Two Streamlit crashes fixed along the way**, both about writing to an already-instantiated widget's own session-state key in the same script run (`StreamlitAPIException`) and a duplicate auto-generated element id across two tabs (`StreamlitDuplicateElementId`, since Streamlit runs every tab's code every rerun regardless of visibility) -- both fixed via patterns already established elsewhere in the codebase (pending-key deferred-apply, explicit widget keys).
- **PDF export mechanism changed twice this session** (`ExportAsFixedFormat` -> `SaveAs(...,32)`; `autoCompressPictures` forced off in `create_ppt`) while investigating an image-pixellation complaint. Neither fully fixed it. A thorough options review (LibreOffice, third-party PDF printers, slide-image export + reassembly, Adobe Acrobat automation) concluded this is a genuine, accepted PowerPoint limitation for now -- see Decision 26. The user's own framing: current output quality is "adequate for current development"; PowerPoint may need reconsidering as the reporting middleware longer-term if this becomes a bigger issue -- not something to act on without being asked.
- **A new shared helper, `core/shared/infrastructure/id_generation.py`**, backs both Stat Tags' and Output Tables' own id issuance (`next_stat_tag_id`/`next_table_id`, separate counters, shared encoding only).
- **A new Architecture principle, "Validate only where designed,"** was added to Structural Design Principles this session, prompted directly by the sizing-clamp bug -- validation/clamping logic is now explicitly an architectural decision, to be raised before adding, not layered in ad hoc while fixing something else.
- **All six governed documents reviewed; four updated** (Feature List, Functional Spec, Architecture, Glossary) -- see Current_State for the itemised list. Primer and Docs Maintenance Guide needed no changes this time.
