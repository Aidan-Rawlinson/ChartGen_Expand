## Status: This session rewrote all 20 Base Chart functions as standalone artefacts (no shared helpers module, no `report_context`) and built the Custom Charts feature end to end — download, AI edit, paste-back validation, live preview, save. Confirmed working live by the user. ### What works (built/fixed this session)

- **Base Charts rewritten as standalone artefacts.** All 20 built-in chart functions moved out of four shape-grouped files into one standalone file each, under `base_charts/{shape}/{chart_type_ref}.py` — no imports from ChartGen's own code, only `matplotlib`/`numpy`. `shared.py` deleted; each file carries its own copy of whatever palette/sizing/formatting helpers it needs. Every chart's signature is now exactly the **chart_inputs** contract — `population_layers, width, height, tweaks` — with `report_context` dropped entirely. This also fixed a real inconsistency: `ranked_column`/`dot_strip` previously found the Selected unit via `report_context.unit_id`, while every other chart used the `"Selected"`-labelled `population_layers` entry; all now use the latter, consistently. `_format_number` (needed by `charts_tab.py`'s own UI, not by any chart) relocated to `core/ui/common/formatting.py` as `format_number`. `registry.py`, `assembly_engine.py`, `charts_tab.py` updated to match. See Architecture Decision 18.

- **Custom Charts feature, built and tested live.** A user (via an AI) can now save a new Base Chart into a workfile. New package `core/output_generation/execution/charts/custom_charts/`: `contract.py` (allowed-imports whitelist, banned-names list, and the shared explainer text — one source of truth for both the gate and the bundle), `gate.py` (static AST validation — exactly one function must match the chart_inputs signature; any number of other-signature helper functions are fine alongside it, matching how every built-in already works), `resolve.py` (built-in registry first, then a workfile's saved custom charts — used at every dropdown/listing site, deliberately *not* at `generation.py`'s auto-default-on-fetch, which stays built-in-only), `bundle.py` (the single self-contained download document: contract + this chart's complete current file, via `inspect.getsource` on the whole module not just the function + live data).
  - **Storage** mirrors the manifest/cache pattern: `WorkfileState.custom_chart_rows`/`.custom_chart_code`, persisted as `workfile_config/custom_charts/custom_charts.csv` + one `.py` per chart under `{shape_type}/{chart_type_ref}.py` — wired into `workfile_file.py`'s load/save.
  - **Dropdowns merged** at all three genuine listing sites — Charts sheet, Running Order edit dialog, Running Order `.xlsx` — via `dialog_support.get_valid_chart_refs_for_cache_file`'s new `custom_chart_rows` parameter.
  - **Charts tab** gained a "Custom Charts" expander: download bundle, paste code, Validate & Preview, Save as custom chart. The in-progress chart (named `temp` if the user names it at all) lives only in ordinary Charts-sheet sandbox state — never written into `WorkfileState`, so it's never a candidate in any dropdown by construction, not filtered out after the fact.
  - **Two real bugs found via live testing, both fixed:** `bundle.py` was using `inspect.getsource(function)` instead of `inspect.getsource(module)`, silently dropping every helper/constant from the download — fixed. `gate.py` was rejecting any file with more than one function *total*, which every built-in already has (its own inlined helpers) — fixed to count only functions matching the chart_inputs signature as the entry point, with any number of other-signature helpers allowed.
  - `contract.py`'s submission instructions tightened twice after review: explicit that the code shown is the complete file and the reply must be the complete file (no diffs, no partial functions), and explicit that the reply should be only the code block — not the live JSON data repeated back.
