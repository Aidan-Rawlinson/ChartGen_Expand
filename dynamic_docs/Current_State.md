## Status: A long session -- the first working "tweaks" feature on any Base Chart (a target reference line on the two CI charts), a real Running Order schema bug found and fixed (a duplicate `tweaks` column silently discarding entered values), a genuine core-system addition (`CG_Chart_`/`CG_Link_` shape naming), a new Running Order support tool (Position Finder), and a COM threading bug fix (`save_pdf` failing on a second run). ### This session's work

**Hyperlink icon redrawn to actually overlap.** The two rounded-rect "links" (Architecture Decision 38) were sitting apart with a small gap, not interlocking the way a real link symbol reads -- the user pointed this out directly. Now overlap by 8 units, centred in the same 72×72 viewBox; since both are stroke-only (no fill), the background shows through the overlap band rather than obscuring it.

**`target` tweak on `column_ci_full` and `line_ci_full`.** The first real per-chart tweaks convention: `target:XXXX` (numeric, or the literal text `median` to track the metric's own median), read via each chart's own `_parse_tweaks` (caret-delimited `key:value^key2:value2`, agreed as a de facto standard other charts may follow but not enforced anywhere). Drawn as a dashed bright-purple (`#9B30FF`) reference line. Per the standing rule, no further chart-specific visual detail is recorded here -- see the code for exact placement, legend integration (moved to the legend as the last entry on `line_ci_full`, rather than an on-chart label, after direct feedback that an on-chart position couldn't be guaranteed clear of other content), and the column chart's own right-edge label treatment.

**Running Order schema bug found and fixed: duplicate `tweaks` column.** `schema.py`'s `COLUMNS` list listed `"tweaks"` twice -- harmless on write (both columns got the same value), but on read, `xlsx_reader.py`'s dict-comprehension row-build silently let the second (blank) column overwrite the first's value for the `tweaks` key. This was the direct cause of the user's reported "I keep losing what I put into tweaks" symptom. Fixed by removing the duplicate. **Any Running Order `.xlsx` already generated under the old schema still has two `tweaks` columns and needs regenerating** -- not something this fix can retroactively repair.

**Decimal-place formatting: a shared "3 significant figures, floor at the unit" rule**, agreed directly with the user rather than inferred: `decimals = max(0, 2 - floor(log10(abs(reference_value))))`, guaranteeing a value is never rounded coarser than its own whole units (5,678 stays 5,678, never 5,680), while extending decimals further for sub-1 values. Applied to `line_ci_full`'s embedded table (decimal count driven by the mean of the table's own values) and to `column_ci_full`'s key/legend values including the bar-top Selected annotation (same shared count, so the same number reads identically wherever it appears on that chart). Scope was deliberately kept to these two charts only, per direct instruction -- not applied to any other Base Chart or Base Table.

**`column_ci_full` legend restructuring, all per direct feedback:** "(this organisation)" dropped from both charts' legends (unit code alone is sufficient); the Mean reference line dropped from the chart entirely, kept as a text-only legend entry (no colour swatch) placed after Median; the Selected-value annotation brought to the top z-order regardless of draw order; a white, 60%-transparent background box added behind both the Selected-value annotation and the Target label, kept in permanently after a live test.

**`save_pdf` COM threading bug fixed.** Failed on a second run with `CoInitialize has not been called` -- `comtypes` was relying on its own implicit, module-level (not per-thread) COM initialisation, which doesn't survive Streamlit giving each script rerun a fresh thread. Fixed with an explicit `pythoncom.CoInitialize()`/`CoUninitialize()` pair around the COM call, matching the convention `insert_from_excel.py` already used for the same reason.

**`CG_Chart_`/`CG_Link_` shape naming, Architecture Decision 40.** `insert_chart` now names the chart picture `CG_Chart_{row_id}` and its optional hyperlink icon `CG_Link_{row_id}`. Exists for general traceback and so a hyperlink icon can be matched back to its own chart by name alone. Keyed on `row_id` by explicit user choice, accepting that the name goes stale once the Running Order is next reordered/edited (`row_id` renumbers) -- a deliberately simpler scheme than a genuinely stable, never-renumbered id.

**Position Finder tool, Architecture Decision 41.** A new read-only Running Order support tool (`core/output_generation/execution/pptx_com/position_finder.py`), not a Running Order function -- a collapsible section under the Running Order tab's own content. Attaches to the currently-open PowerPoint via `GetActiveObject` (never launches a new instance), reads the selected shape's live position/size (points, converted to EMU), and, for a `CG_Link_` icon, resolves its position as an offset from its matching `CG_Chart_` shape -- the same convention `hyperlink_left`/`hyperlink_top` already use -- falling back to the icon's own absolute position with an explanatory note if no match is found on the slide. Never writes back to the presentation or the Running Order.

**Governed docs updated for all of the above** -- Architecture (Decision 16 corrected, new Decisions 40-41), Functional Spec (Section 10.3 corrected, new Section 9.7), Feature List, Glossary. Primer untouched -- nothing this session changed domain rationale or design intent.
