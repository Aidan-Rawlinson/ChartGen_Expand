## Status: This was a very large session. Built, in order: NHS chart-title placeholder replacement; the Chart Store feature from scratch; an EMU-only unit consolidation across every Base Chart and Base Table; the full "charts inside table cells" feature (chart-component cells, layered PPTX insertion, Preview SVG splice); a trim of Base Tables from ten styles to two while working through precise chart-cell positioning on both; and several live-testing bug fixes along the way. ### What works (built/changed this session)

**NHS chart-title placeholder replacement.** Reverse-engineered from the user's old Excel/VBA process (`PROCESS_URL`/`Option_Text`). `core/acquisition/toolkit_nhs/transformers.py`: new `_resolve_title()` strips literal `*` wildcards and replaces nine year tokens (`|DOUBLE_YEAR_CURRENT|` etc.) plus `|OPTION_TITLE|` (resolved from `data["options"]["denominators"][option]["titleOptionName"]`), applied once in `transform()` after shape dispatch (not duplicated per shape type); `transform()` and `fetch.py`'s call site both take a new `option` parameter (already parsed from the URL by `url_parser.py`, 0-indexed, default 0). Pie charts also get the resolved title applied to their single metric's `name` (which `dot_matrix.py` draws directly on the chart), reusing the same resolved string rather than resolving twice.

**Chart Store — a flat, unordered store of independently-authored chart-defs, for future/now-actual use as chart components inside Output Table cells.** New `chart_store.py` (`next_chart_store_id`, `chart_store_row_label`), `chart_store_xlsx.py` (full-replace Excel round-trip, mirroring `stat_tags_xlsx.py`). `workfile_file.py`: `CHART_STORE_FIELDNAMES`, `WorkfileState.chart_store_rows`, read/write of `workfile_config/chart_store.csv`. `charts_tab.py`: a third entry point ("Chart Store line") alongside Running Order row and Data shape, positioned second (before Data shape) so its own pending-field staging lands before the shared `cs_pending_shape_choice` consumption step runs — this ordering is load-bearing, not cosmetic (see bug fixes below); a "Save to Chart Store" expander (Add/Overwrite only, no position concept, unlike Running Order's Overwrite/Insert-above/below); a "Show Chart Store" / "Hide Chart Store" toggle that replaces the whole right-hand chart preview with a read-only table of every entry (delete/download/upload) — the two are never shown together, by design. Sandbox persistence (`charts_sheet_state`) extended to remember the Chart Store selection/target/action across Save+reopen.

**Stat Tag and Chart Store ids now carry a one-letter prefix** — `T` for Stat Tags (`stat_tags.py::next_stat_tag`), `C` for Chart Store (`chart_store.py::next_chart_store_id`) — so the two can coexist unambiguously once both can appear inside the same Output Table cell. Pure string concatenation on top of the existing base-36 counters; old, unprefixed ids already in a workfile keep working untouched, only newly-issued ids get the prefix.

**EMU consolidation — the old percent-of-a-fixed-7.5in-reference conversion is gone.** Every one of the 20 Base Charts and (at the time) 10 Base Tables now takes `width_emu`/`height_emu` directly, not `width`/`height` percent. `assembly_engine._render_chart_image` and `insert_table.py` pass EMU straight through — no conversion at either call site any more. Percent survives in exactly one place: the Charts sheet's and Output Tables tab's own Sizing widgets, converting to/from EMU immediately at that boundary (`page_sizing.py`, unchanged) and never travelling further. `chart_inputs`/`table_inputs` contracts and both `gate.py`'s own enforced `REQUIRED_PARAMS` were updated to match — this is a breaking change for any Custom Chart/Table saved under the old contract (mirrors the SVG-methodology precedent); no live ones were known to exist. Custom Charts/Tables `contract.py` and `bundle.py` updated to describe/use the new parameter names throughout.

**Charts inside table cells — the actual feature this whole session built toward.** A grid cell holding the literal marker `{Cn}` (a Chart Store id) is recognised by the Base Table function itself (plain string check — starts with `{`, ends with `}`, inner text starts with `C` — no regex needed, so a Custom Table author doesn't need `re` added to `ALLOWED_IMPORTS`), not drawn as text, and the function reports back the exact rectangle it reserved for it. Every Base Table now returns `(image_bytes, chart_cells)`, `chart_cells` being `{tag: {"x","y","width","height"}}` in EMU. Two different consumers, deliberately two different mechanisms: `insert_table.py` (final report) renders the named Chart Store entry to fit the cell's own rectangle — never the entry's own stored size — via the same cache-load/cut/population-layers/render pipeline `insert_chart` uses, and inserts it as a second, layered PowerPoint picture; `output_tables_tab.py`'s Preview instead splices each chart in as a nested `<image>` data-URI inside the table's own SVG string, positioned in **percent** of the table's declared canvas (not EMU/pixels) so it stays aligned with the cell borders regardless of whatever the browser or any crop does to the outer SVG.

**"The cell" is a per-style design decision, not a geometry lookup.** Established explicitly with the user across two rounds of live testing and correction (see Decisions.md for the full back-and-forth): a style's own padding/border/shadow/rounding can mean the reported rectangle is deliberately smaller than the raw grid cell. `table_cardtile.py`'s own card is one shared rounded rectangle per row (not per cell) — a chart cell there now reports the card's own vertical inset (`card_y`/`card_h`, excluding the shadow and the 10% top/bottom margin), and each column's own horizontal share of that shared card (column 0 was found and fixed to have been wrongly reporting the *entire* row width). The header row has no card at all, so a chart cell there just reports the raw grid cell — nothing to narrow it against.

**Two different, verified fixes for cell-position precision, not one general mechanism.** `plain_grid.py`: dropped `bbox_inches="tight"` entirely (nothing in it draws outside its own axes) and made its axes fill the whole figure explicitly (`fig.add_axes([0,0,1,1])` instead of `tight_layout`) — the 0–100 data space then maps onto the declared canvas exactly, nothing to correct for. Verified empirically in a sandbox (rendered the real setup, predicted a cell's SVG path coordinates from the formula, extracted the actual drawn path, confirmed an exact match) before touching the real file. `table_cardtile.py` genuinely needs `bbox_inches="tight"` (its drop shadow is drawn with `clip_on=False` specifically so it isn't clipped off) — so instead it calls `fig.get_tightbbox(renderer)` after all drawing is complete (the same computation `bbox_inches="tight"` itself uses, read directly) and remaps every cell's data-space coordinates through the actual crop bounding box plus `pad_inches` before converting to EMU (`_resolve_chart_cells`). Also verified empirically the same way; the first verification attempt showed a small mismatch that turned out to be a debug artist *I'd* added corrupting the measurement, not a flaw in the method — corrected and reverified against a real, already-drawn artist instead.

**Base Tables trimmed from ten styles to two, the other eight deleted outright** (`table_brutalist`, `table_editorial`, `table_freeform`, `table_ledger`, `table_pill`, `table_softui`, `table_terminal`, `table_zebra` — files and their `__pycache__` gone; `registry.py`/`__init__.py` updated). Explicit user decision, at the user's own request, once the `bbox_inches="tight"` precision trap above surfaced as a genuinely harder problem than first assumed for any style with deliberately-overflowing decoration. `plain_grid` and `table_cardtile` kept — the simple crop-free case and the harder tight-bbox-correction case, respectively — as the two reference implementations for whatever comes next.

**Standing guidance for whoever builds a new Base Table lives in the Custom Tables bundle (`custom_tables/contract.py`), not in code comments elsewhere.** The user was explicit about this: bundle export/import (download → AI edits → paste back) is practically the only way a Base Table actually gets built or modified going forward, so guidance placed anywhere else (an earlier attempt put it in `base_tables/__init__.py` too, which the user then had removed) would not reach whoever's doing that work. Covers both "the cell is a design decision" and the `bbox_inches="tight"` trap, with the fix pattern spelled out.

**All four governed docs updated in the mirror** — Architecture gained two new Decisions (29: EMU consolidation; 30: charts inside table cells, covering the marker syntax, the return-contract change, the two rendering mechanisms, the "cell is a design decision" principle, why eight styles were deleted, and the two different precision fixes), plus package-tree/component-table/column-schema touch-ups. Feature List, Glossary, and Functional Spec updated to match (id-prefix examples, EMU parameter names, the two-style Base Table library, chart-component cells flipped from Not built to Complete). ### Bugs found and fixed during live testing this session (all resolved)

- **Chart Store line not triggering the rest of the sandbox to load.** Root cause: it sat *after* the Data shape selectbox in the code, but the shared pending-consumption step runs *before* Data shape — a widget already instantiated in a Streamlit run can't be changed retroactively. Fixed by moving Chart Store line to sit *before* Data shape (second position, after Running Order row), matching how Running Order row itself already worked; no rerun needed once reordered correctly.
- **Chart Store dropdown showing a stale/wrong-seeming entry after selecting a Running Order row (or vice versa).** The two entry points weren't mutually exclusive — selecting one didn't clear the other's own bookkeeping. Fixed via `_clear_chart_store_referencing_state()`/`_clear_row_referencing_state()`, called from each other's load branch (with a forced rerun only where needed, since one selector renders before the other in the same pass).
- **Sizing box occasionally reverting to its minimum value (1) right after a Save (Chart Store or Running Order).** Root cause: the post-save "rebind to what was just saved" step deliberately cleared the *last-loaded* bookkeeping so the dropdown would show the fresh entry — but that made the very next script run treat the rebind as a brand-new user selection, re-triggering the entire field-reload path (including Sizing) unnecessarily, on every single save. Fixed by syncing the last-loaded value instead of clearing it, in both `charts_tab.py` and `output_tables_tab.py` — the reload path is now skipped entirely after a save, since the sandbox already holds the correct values.
- **Reset button (and the reset-on-placeholder-reselection path) silently reloading the *previous* saved state instead of giving a blank sandbox.** `_clear_sandbox_state()` was wiping `cs_tab_rendered` along with everything else, which made the very next render treat the sheet as freshly opened and re-trigger the once-per-Open restore-from-settings. Fixed by preserving `cs_tab_rendered` specifically, matching a pattern `output_tables_tab.py` already had for the identical reason.
- **`KeyError` on any Custom Tables bundle download** (`'" followed by an id followed by "'`). The Custom Tables contract's `TABLE_INPUTS_EXPLANATION` template string had literal, unescaped `{`/`}` characters in prose describing the `{Cn}` marker syntax — `.format()` tried to treat them as placeholders. Fixed by escaping every literal brace to `{{`/`}}`; verified no equivalent issue existed in the parallel `custom_charts/contract.py`.
