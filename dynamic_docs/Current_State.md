## Status: This session replaced raster (PNG) rendering with SVG across every Base Chart and Base Table, following a live spike-and-prove cycle on one table type first (`table_cardtile`) before rolling the proven methodology out to the full fleet. Standard font is now Calibri, baked into vector outlines rather than live text. PDF export reverted to `ExportAsFixedFormat` with default settings, at the user's request. Architecture and Feature List updated in the mirror; re-upload done this close-down.

### What works (built/changed this session)

- **SVG rendering methodology -- every Base Chart (20) and Base Table (10) now renders as SVG, not PNG.** `fig.savefig(..., format="svg")` in place of `format="png"`, inserted into the PowerPoint template as a native SVG picture rather than a rasterised one. See Architecture Decision 27.
  - **Insertion mechanism.** A new shared helper, `core/output_generation/execution/svg_insert.py` (`add_svg_picture`), hand-builds the OOXML dual-blip an SVG picture requires (fallback raster + a separate SVG part, wired via an `<a:extLst>` extension on the `<a:blip>`) since `python-pptx`'s own `add_picture()` has no concept of SVG. Used identically by `insert_chart` (`assembly_engine.py`) and `insert_table` (`tables/insert_table.py`) -- both call sites are unconditional now, no per-type branching.
  - **Font: Calibri**, set via `matplotlib.rcParams["font.family"] = "Calibri"` in every Base Chart/Base Table file. `svg.fonttype` is left at matplotlib's own default (`"path"`) -- text becomes vector outlines, not live `<text>` elements. The alternative (`"none"`) was tried and reverted: it didn't make text genuinely searchable/selectable in PowerPoint or either PDF export pathway, and corrupted character positioning in the PDF specifically.
  - **`table_cardtile` deduplicated.** Built first as a live spike copy (`table_cardtile_svg.py`) alongside the original raster `table_cardtile.py`, proven out, then merged back into the single `table_cardtile.py` file once the methodology was settled -- no separate `_svg` file remains anywhere.
  - **Both Preview sandboxes updated** (Charts sheet, Output Tables tab) -- `st.image()` can't decode SVG (it goes through PIL), so both now render via `st.markdown()` with a small `_svg_preview_html()` helper (each tab's own copy, not shared) that forces the SVG to the same pixel width the raster path used to compute, so zoom levels still behave consistently.
  - **Custom Charts/Custom Tables contract documents updated** (`custom_charts/contract.py`, `custom_tables/contract.py`) -- the downloadable bundle now tells an AI to return SVG bytes and set `font.family = "Calibri"`, and explicitly warns against `svg.fonttype = "none"`.
  - **DPI.** Base Charts no longer have a DPI constant at all (was only ever used for the now-removed `dpi=` savefig argument). Base Tables keep `DPI = 300` (down from a temporary `450` used mid-investigation), used only for matplotlib's own text-metric estimation during layout -- no bearing on the SVG's own resolution.
- **PDF export mechanism reverted to `ExportAsFixedFormat`, default settings, at the user's explicit request** (`save_pdf`, `assembly_engine.py`) -- `deck.ExportAsFixedFormat(pdf_path, 2)`. Two intermediate variants were tried and abandoned first (`ExportAsFixedFormat` with `Intent=2`/`BitmapMissingFonts=False`; `SaveAs(path, 32)`) -- neither changed the specific PDF text-positioning corruption under investigation, so the simplest version was kept. See Architecture Decision 26 (revised this session).
- **Both Architecture and Feature List updated in the mirror** -- Decision 26 revised (current PDF export mechanism), new Decision 27 (the full SVG methodology write-up). Feature List's Base Chart library and Base Table library rows both note the SVG/Calibri change and the searchability limitation. Functional Spec, Glossary, Primer, and the Docs Maintenance Guide needed no changes -- none of their existing wording specified a raster format, so nothing they say became false.

### Known gaps / not yet done (carried forward or new)

- **Table/chart text is not searchable or selectable in PowerPoint or the exported PDF, regardless of `svg.fonttype`.** Tried both settings; neither exposes the text to PowerPoint's own Find or the PDF's text layer, since both treat an embedded SVG as an opaque picture. Accepted as a structural limitation, not a tunable setting. See Architecture Decision 27.
- **Unhinted vector text (an `svg.fonttype="path"` side effect) renders thin vertical strokes fractionally too heavy in some PDF viewers (confirmed in Adobe Reader) at low zoom** -- disappears at higher zoom or in print. Cosmetic, accepted. See Decision 27.
- **Any Custom Chart or Custom Table saved before this session's methodology will fail insertion outright**, since both insertion call sites now assume SVG bytes unconditionally with no raster fallback. None are known to currently exist in any live workfile beyond a prior session's one-off `ranked_column` Custom Chart test -- worth checking before this surprises anyone.
- **`table_ledger`'s explicit `fontfamily="serif"` override was left alone**, not switched to Calibri -- read as a deliberate per-table aesthetic choice (the table's own "ledger/accounting" look) rather than something this session's font-default change was meant to touch. Flagged, not actioned.
- **PDF export's raster-downsampling finding (Decision 26) still applies to `insert_picture`** (arbitrary user-supplied images placed via a yellow box), which remains a raster path -- untouched by this session's SVG work, which only covers Base Chart/Base Table output.
- **Custom Tables round-trip testing still not done at all** (carried forward, unrelated to this session's work) -- built and wired in a prior session, never taken through a full download/edit/paste-back/save loop.
- **A manually-created Output Table still has no automatic Running Order placement** (carried forward) -- only a yellow-box-created one gets an `insert_table` row for free.
- **`chart_type_ref` -> `base_chart_name` rename still agreed in principle, still deliberately deferred** (carried forward) -- breaking change, needs its own dedicated session.
- **Chart-component cells (`{n}`) in Output Tables remain parked** (carried forward) -- recognised by the grid's own grammar, not resolved or rendered.

### Resolved this session

- Raster pixellation in embedded charts/tables (on screen and on PDF export) -- resolved via the SVG rendering methodology (Decision 27), for every Base Chart/Base Table's own output specifically.
- Letter-spacing/kerning corruption from font substitution (matplotlib's implicit default, DejaVu Sans, not present on the rendering machine) -- resolved by setting an explicit, confirmed-present font (Calibri) rather than leaving it to matplotlib's own fallback.
- `table_cardtile_svg.py` spike copy -- folded back into the single `table_cardtile.py` file; no duplicate table type remains.
