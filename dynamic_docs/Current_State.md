### New Base Charts built this session (code only -- not documented, per the standing rule)

Registered under `base_charts/timeseries/`, `chart_type_map.csv` (TimeSeries unless noted), `registry.py`:

- **`sparkline1`** -- population-median line + Selected unit's own submission line, no axes. Went through many refinement rounds this session: transparent background; a height-based border with independently-tunable inner/outer gaps around the end labels (fixed physical inches, not axes-fraction, after an axes-fraction approach was found to entangle gap size with the auto-measured label margin); `bbox_inches="tight"` removed entirely so the returned SVG is always exactly `width_emu x height_emu` (a real bug this session: the chart was previously squishing/distorting when a downstream consumer had to stretch a wrongly-shaped file back to the requested size); a 4-sided inset mechanism (`_inset_axes_to_fit`) that measures actual overflow and reserves real margin rather than cropping, with the margin cap later removed entirely at the user's explicit request; a fix for a genuine crash (`'<' not supported...` on a `None` reaching `min()`/`max()`) that was first over-corrected to suppress the whole line for a single missing month, then properly fixed to draw a real gap only at the missing period(s), plus a dotted "bridge" connector across an internal gap flanked by real data on both sides; line/marker sizes, gradient fill, and label positioning tuned over several further rounds.
- **`celltest`** -- diagnostic only: a 50%-transparent green rectangle at exactly the requested size, for checking cell/chart alignment. Registered across all four data shapes (shape-agnostic).
- **`line_has_data`** -- diagnostic: grey circle, white tick/cross for whether the Selected unit's submission has *any* non-null value (looser than `sparkline1`'s own all-or-nothing gate).
- **`line_ci_median` / `line_ci_2` / `line_ci_5pct` / `line_ci_0_5pct`** -- a family of three-way pass/fail/no-data indicators, checking only the *final* period's submission value against a threshold (population median, or a fixed 2/5%/0.5%). Circle fill carries the result (blue pass, orange fail -- a genuine HLS colour-wheel complement of the pass blue, not just "an orange" picked freehand -- grey no-data); the tick/cross/dash mark itself is always white.

### New Base Tables built this session (code only -- not documented, per the standing rule)

**`ci_grid`** and **`ci_cardtile`** -- tailored variants of `plain_grid`/`table_cardtile` respectively, registered in `base_tables/registry.py`. Both add: a two-row header (leading columns merged into one cell spanning both header rows; the final two columns get a merged "Benchmark" label in row 0 and fixed "Target"/"Met(?)" sub-headings in row 1, neither read from resolved content); blank-row suppression (a body row with every cell empty draws nothing at all -- no border/card/shadow/text -- while its row height is still reserved, so a fixed row count with trailing blank rows gives consistent sizing across tables with different real row counts). `ci_cardtile` additionally went through several rounds of header-specific styling: a rounded, drop-shadowed header block using the exact same shadow-offset technique and values as a body card (not a separately-derived fraction, which had produced a visibly bigger shadow gap than the body cards'); a gradient background fill; darker header text (matched to `sparkline1`'s own derived label colour, not the flat base blue); a font-size boost for header text sourced from row 0; centred (not right-aligned) alignment for header text and one specific body column.

### Core-system fixes this session (documented -- see Architecture Decisions 31-34)

- **Chart Store population inheritance for table-cell rendering** (Architecture Decision 31) -- a Chart Store entry's own blank `populations` field wasn't inheriting the Running Order's current default when rendered inside a table cell (both the final-report path and the Preview splice), despite rendering correctly everywhere else. Fixed in `insert_table.py` (reads `ctx.default_populations`) and `output_tables_tab.py` (reads the workfile's own `set_default_populations` row directly, mirroring the Charts sheet's own Preview fallback).
- **Chart Store id issuance made self-healing** (Architecture Decision 32) -- `next_chart_store_id` could reissue an id already in use if its persisted counter had fallen behind (confirmed: an Excel-uploaded row with its own id already filled in never advances the counter). Fixed by resyncing the counter against every id actually in use (`id_generation.from_base36`, the new inverse of `to_base36`) before issuing a new one, at both entry points.
- **Line breaks in Output Table content, `<br>`** (Architecture Decision 33) -- a typed `<br>` (also `<br/>`/`<br />`) is now converted to a real newline in `resolve.py`, the one shared point both rendering paths already resolve content through. Paired with a new height-aware font-fit step added to both `plain_grid.py` and `table_cardtile.py` (`_shrink_for_multiline_height`), since the existing width-only fit could leave a genuine second line silently painted over by the next row.
- **Excel percentage values read via number format, not raw cell value** (Architecture Decision 34) -- `grid_xlsx.py` was reading `cell.value` directly, so a cell where Excel auto-applied a Percentage format (typing `5%`) came back as the literal text `"0.05"`. Fixed via a `_cell_text` helper that checks `cell.number_format` and reconstructs the percentage string when present. Flagged, not yet checked: the same gap may exist in the other Excel round-trip readers (Stat Tags, Chart Store, Running Order).
